# وضعیت مرجع پروژه RelayOnDuration

این فایل معرفی و راه‌اندازی سریع پروژه است. تاریخچه تصمیم‌ها، وضعیت آخرین نوبت و کارهای باز در فایل مستقل [PROJECT_STATUS.md](PROJECT_STATUS.md) نگه‌داری می‌شود. قبل از هر تغییر، آن فایل و گزارش `docs/relay_on_duration_report.tex` کامل خوانده شوند.

## هدف محصول

فریم‌ور STM32F107VCT6 برای پایش و کنترل اتاق آزمون تجهیزات برودتی است. دو ایستگاه، ۳۲ حسگر DS18B20 را روی دو گذرگاه 1-Wire می‌خوانند؛ دو DS18B20 دیگر دمای محیط را می‌دهند؛ رطوبت از سنسور آنالوگ HIH روی ADC گرفته می‌شود؛ ADE7880 ولتاژ، جریان و توان دو کانال را می‌خواند؛ رایانه از طریق RS-232 فرمان می‌دهد و قاب ۲۰۹ بایتی دریافت می‌کند. خروجی‌های رطوبت‌ساز، سرمایش، هیتر/SSR و رله ایستگاه فعال‌پایین‌اند.

## وضعیت فعلی — ۱۴۰۵/۰۶/۲۳ (2026-09-14)

- کد کاربردی از `main.c` و `stm32f1xx_it.c` خارج و در `Core/Src/app.c` متمرکز شده است.
- فایل‌های مولد فقط HAL و دو نقطه اتصال `App_Init` و `App_Process` را دارند؛ منطق سنگین دیگر داخل ISR نیست.
- UART با `HAL_UART_Receive_IT` و callback تک‌بایتی کار می‌کند؛ فرمان در حلقه اصلی پردازش می‌شود.
- جدول سنسورها در آخرین صفحه Flash، آدرس `0x0803F800`، با magic/version/CRC ذخیره می‌شود. داده معتبر قدیمی `0x08009000` یک‌بار مهاجرت می‌شود.
- آخرین صفحه Flash در Keil و linker script مربوط به PlatformIO از کد رزرو شده است.
- `TIM2.Period` در `.ioc` با سورس عملیاتی روی ۳۵۹۹ همگام شده است؛ نرخ تقریبی ۲ هرتز است.
- حالت خاموش خودکار همه خروجی‌های شناخته‌شده را به وضعیت امن می‌برد.
- دو LED عیب‌یابی روی PC13 و PC14 با الگوی غیرمسدودکننده فعال‌اند؛ رقص یک‌ثانیه‌ای نشان‌دهنده اجرای حلقه اصلی و تناوب سریع نشان‌دهنده ورود به `Error_Handler` است.
- قاب سریال قدیمی ۲۰۹ بایتی، ترتیب بایت‌ها، ضرایب کالیبراسیون و آدرس‌های پیش‌فرض حفظ شده‌اند.
- گزارش فارسی ماژولار XePersian در `docs/` ساخته شده است.
- ساخت PlatformIO با framework-stm32cubef1 1.8.7 موفق است: ۲۰۷۹۶ بایت Flash و ۱۲۴۰ بایت RAM در آخرین ساخت.
- گزارش تفصیلی با XeLaTeX در ۵۴ صفحه و بدون خطای ساخت، نویسه مفقود یا اخطار overfull/underfull تولید شده و همه صفحه‌ها پس از رندر بصری بازبینی شده‌اند.
- XML پروژه Keil معتبر است، ولی Keil در محیط فعلی نصب نبود؛ build مجدد Keil هنوز باید روی سیستم توسعه انجام شود.
- این مسیر هنگام ممیزی Git repository نبود؛ خروجی‌های قدیمی Keil عمداً حذف نشدند و `.gitignore` برای مخزن آینده افزوده شد.

## ساختار مالکیت فایل

- تولیدشده با CubeMX: `Core/Src/main.c`, `Core/Src/stm32f1xx_it.c`, `Core/Src/stm32f1xx_hal_msp.c`, سرآیندهای HAL و `STM32F107.ioc`.
- کد محصول و قابل ویرایش: `Core/Src/app.c`, `Core/Inc/app.h`.
- ذخیره پایدار: `Core/Src/sensor_address_store.c`, `Core/Inc/sensor_address_store.h`.
- نشانگر اجرا و خطا: `Core/Src/diagnostic_led.c`, `Core/Inc/diagnostic_led.h`.
- درایورهای محلی: ADE7880، DS18B20، AM2315 و MAF در `Core/`.
- ابزار ساخت: `MDK-ARM/STM32F107.uvprojx`, `platformio.ini`, `STM32F107VC_FLASH.ld`.
- مستندات: `docs/relay_on_duration_report.tex`, `docs/report-config.tex`, `docs/chapters/`.

## قراردادهای تغییر

1. در فایل‌های CubeMX فقط داخل USER CODE block کد دستی بنویسید.
2. منطق جدید را در ماژول مستقل قرار دهید و ISR را کوتاه نگه دارید.
3. پس از تولید مجدد، عضویت `app.c` و `sensor_address_store.c` در پروژه Keil و مقدار IROM1 برابر `0x3F800` را کنترل کنید.
4. آخرین صفحه Flash هرگز نباید وارد ناحیه لینک شود.
5. قالب سریال را بدون نسخه‌بندی و هماهنگی نرم‌افزار PC تغییر ندهید.
6. هر تغییر رفتاری باید در گزارش و فایل `PROJECT_STATUS.md` ثبت شود.
7. فایل‌های خروجی `MDK-ARM/STM32F107/` مرجع تاریخی‌اند، نه نتیجه build سورس جدید.

## فرمان‌های ساخت

PlatformIO:

```text
pio run
pio run --target upload
pio device monitor
```

قطب پیش‌فرض LEDهای PC13/PC14 فعال‌پایین است. اگر LED از پایه به مقاومت و سپس زمین متصل شده، مقدار `DIAGNOSTIC_LED_ACTIVE_LOW` در `Core/Inc/diagnostic_led.h` باید صفر شود. برای هر LED مقاومت سری مستقل لازم است.

Keil: فایل `MDK-ARM/STM32F107.uvprojx` را باز، Build و سپس با J-Link/SWD پروگرام کنید.

گزارش:

```text
cd docs
xelatex -interaction=nonstopmode relay_on_duration_report.tex
xelatex -interaction=nonstopmode relay_on_duration_report.tex
```

## موارد استفاده‌نشده یا ناقص

- AM2315 و I2C1 در مسیر فعال استفاده نمی‌شوند؛ درایور اکنون CRC16 را بررسی می‌کند اما تست سخت‌افزاری نشده است.
- MAF در Keil عضو نیست و فراخوانی ندارد.
- کانال دوم ADC خوانده می‌شود ولی مصرف کاربردی ندارد.
- فاز C و جریان نول ADE7880 قابل خواندن‌اند ولی ارسال نمی‌شوند.
- Fundamental power API در ADE7880 برای قابلیت جدید قابل اتکا نیست؛ توابع کاملاً خالی FVRMS/FIRMS حذف شده‌اند.
- پایه‌های PE3، PE6، PB4، PD0، PD2، PD3، PD8، PD14، PD15 و PC8 خروجی تعریف شده‌اند اما نقش فعالشان از سورس معلوم نیست.
- ایستگاه‌های سوم و چهارم فقط فضای رزرو صفر در پروتکل دارند.

## ریسک‌های باز و آزمون‌های الزامی

- هنوز هیچ آزمون روی برد برای نسخه بازآرایی‌شده انجام نشده است.
- active-low بودن همه خروجی‌های قدرت باید بدون بار و با مولتی‌متر تأیید شود.
- درایور 1-Wire زمان‌بندی حلقه‌ای وابسته به کامپایلر دارد، CRC scratchpad ندارد و پایان conversion را درست poll نمی‌کند؛ اولویت فنی بعدی است.
- حفاظت minimum on/off time کمپرسور و watchdog وجود ندارد.
- پروتکل سریال checksum، resync و پاسخ خطای رسمی ندارد.
- ضرایب HIH و ADE7880 باید با مرجع کالیبراسیون واقعی تأیید شوند.
- همه ۳۲ ROM پیش‌فرض و مسیر migration Flash باید روی سخت‌افزار تست شوند.
- نرم‌افزار PC باید فرمان‌ها را دقیقاً در قاب ۱۲ بایتی بفرستد.

## ترتیب پیشنهادی ادامه

1. Build هر دو toolchain و رفع همه warningهای واقعی.
2. تست GPIO امن بدون بار، سپس UART loop/protocol.
3. تست یک حسگر روی هر bus و بعد بار کامل ۳۲ حسگر.
4. تست Flash با قطع و وصل برق.
5. تست ADE7880 با منبع مرجع.
6. تست کنترل محیط با بار شبیه‌ساز؛ سپس افزودن حفاظت کمپرسور و watchdog.
